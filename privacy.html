Privacy Policy

Last updated: May 2026  |  Effective: May 2026

This Privacy Policy explains how the zonov.ai Chrome Extension ("Extension", "we", "our") collects, uses, stores, and shares information when hospital staff ("User", "you") use the Extension. Please read this policy carefully before using the Extension.

Important: This Extension processes sensitive personal and biometric data including Aadhaar card details and facial recognition descriptors. All data handling is described transparently below. By using this Extension, you confirm you are authorised hospital staff and that patients have given appropriate consent for their data to be processed.

1. What the Extension Does

zonov.ai is a hospital productivity tool designed exclusively for authorised medical registration staff. It helps fill patient registration forms in Hospital Information Management Systems (HIMS) using three AI-powered features:

  • Aadhaar / ID Card Scan — Camera or gallery image → OCR extracts patient data → auto-fills the HIMS form
  • AI Voice Fill — Microphone recording → speech-to-text → fills empty form fields
  • Return Patient Face Match — Camera captures face → matches against stored face descriptors → retrieves patient record and auto-fills form

2. Data We Collect and Why

2a. Patient Identity Data (from Aadhaar / ID Card Scan)

When a staff member scans an ID card, the following patient data is extracted and stored in our cloud database:

  • Full name, date of birth, gender
  • Aadhaar number (12-digit UID)
  • Father's name / guardian name
  • Residential address, PIN code, district, state
  • Mobile number, email address (if present on card)

Purpose: To populate the HIMS registration form and to enable returning patient lookup so the same patient does not need to be re-registered on future visits.

Storage: Stored in a private Supabase PostgreSQL database (nnzozslhgdmgnfhtadoq.supabase.co) scoped to your hospital's ID. Each hospital's data is logically isolated by a hospital_id column with Row-Level Security (RLS) policies enforced at the database level.

2b. Facial Biometric Data (Face Descriptors)

If a staff member registers a patient's face for future recognition, the Extension captures a camera frame and generates a 128-dimensional numerical face descriptor (a mathematical representation, not a photograph) using the open-source face-api.js library running entirely on-device (CPU, no GPU).

What is stored: Only the numerical descriptor array — not the photograph itself. The raw camera image is never uploaded or stored.

Storage: Descriptor stored in the Supabase database linked to the patient record. Used only to match returning patients; never used for any other purpose.

Biometric Data Notice: Facial descriptors constitute biometric data under applicable data protection laws (including India's DPDP Act 2023 and GDPR). Hospital operators are responsible for obtaining valid patient consent before enrolling a patient's face in the system. zonov.ai provides the technical infrastructure only.

2c. ID Card Images (sent for OCR processing)

When a card is scanned, the captured image is sent to Groq API (a third-party AI service) for text extraction. The image is sent as a one-time API request and is not stored by zonov.ai. Groq's data handling is governed by Groq's Privacy Policy.

2d. Voice Recordings (AI Voice Fill)

When Voice Fill is activated, microphone audio is captured and sent to Groq API for speech-to-text transcription. The transcript is used to fill form fields and is not stored. Audio recordings are not retained by zonov.ai after transcription.

2e. Staff Authentication Data

Staff log in using email and password via Supabase Authentication. Passwords are never stored by the Extension — only the encrypted session token is stored locally in chrome.storage.local on the staff member's device.

2f. Form Field Memory (Local Only)

The Extension learns which form labels correspond to which data fields (e.g., "Patient Name" → name field) to improve accuracy over time. These mappings are stored locally in chrome.storage.local and contain only label strings — never patient data. Cleared on uninstall.

2g. Hospital UHID / Registration Numbers

After a patient is registered in HIMS, staff may save the hospital-assigned UHID/Reg No to link it to the patient record in Supabase. This is used for future record lookup.

4. Third-Party Services

  • Groq (api.groq.com) — Receives ID card images (for OCR) and voice transcripts (for speech-to-text). Data handled per Groq's Privacy Policy. No data is stored by Groq beyond their standard API processing terms.
  • Supabase (supabase.com) — Cloud PostgreSQL database used to store patient records and face descriptors. Data handled per Supabase's Privacy Policy. Data is stored in the project region and protected by Row-Level Security.

The Extension does not share data with any advertising networks, analytics platforms, or any third party beyond those listed above.

6. Data Retention

  • Patient identity records — retained in Supabase until the hospital administrator deletes them via the dashboard.
  • Face biometric descriptors — retained in Supabase until deleted by hospital administrator.
  • Voice recordings — not retained; discarded after transcription.
  • ID card images — not retained; discarded after OCR response.
  • Local storage — cleared when the Extension is uninstalled.

7. Data Subject Rights

Patients whose data is processed through this Extension have rights under applicable law (DPDP Act 2023, GDPR where applicable), including the right to access, correct, or delete their data. These requests should be directed to the hospital where the data was registered. Hospital administrators can delete patient records via the zonov.ai dashboard or by contacting arvind@zonov.ai.

8. Security

All communication with Supabase and Groq uses HTTPS/TLS encryption. The Supabase database enforces Row-Level Security (RLS) so each hospital's data is isolated — staff at Hospital A cannot access Hospital B's patient records. Session tokens are stored locally and never transmitted in plaintext.

9. Intended Audience

This Extension is intended exclusively for use by authorised hospital staff and medical professionals. It is not directed at the general public or children. Access is controlled by hospital-issued credentials managed through Supabase Authentication.

10. Changes to This Policy

We may update this Privacy Policy as features change. The "Last updated" date at the top will reflect any changes. Continued use of the Extension after changes constitutes acceptance of the revised policy.
